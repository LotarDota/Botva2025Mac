Уязвимости безопасности

SSL-сертификат истекает через 12 дней
CRITICAL CVSS 9.8
Сертификат (GlobalSign AlphaSSL) истекает 19 мая 2026. После истечения срока все HTTPS-соединения перестанут работать, браузеры покажут предупреждения безопасности, и пользователи не смогут зайти в игру. Механизм автопродления не обнаружен.
Админ-панель публично доступна
CRITICAL CVSS 9.1
/admin/ возвращает 200 OK на ВСЕХ игровых серверах с полным HTML, включая jQuery UI, пользовательские скрипты (/admin/script.js) и стили. Показывает сообщение «Only debug mode» — но раскрывает структуру админки, JS-эндпоинты и может быть обойдена. Использует устаревший jQuery 1.10.2.
<title>Test zone</title> <script src='/admin/script.js?v=201104141'></script> <script src='https://i.botva.ru/css/jquery-1.10.2.min.js'></script>
Отсутствие CSRF-защиты на входе/регистрации
CRITICAL CVSS 8.8
Формы входа (login.php, login.php?type=name) и восстановления пароля (login.php?a=forgot) не содержат CSRF-токенов. Злоумышленник может создать вредоносную страницу, которая автоматически отправляет формы входа с учётными данными жертвы или принудительно сбросить пароль.
<!-- No CSRF token anywhere in the form --> <form method="POST" action="login.php" class="submit_by_ajax"> <input type="hidden" name="do_cmd" value="login"> <input type="text" name="email" placeholder="E-mail"> <input type="password" name="password" placeholder="Password"> </form>
crossdomain.xml разрешает все домены (*)
CRITICAL CVSS 8.6
Все игровые сервера отдают crossdomain.xml с <allow-access-from domain="*" />. Это позволяет любому Flash/Silverlight-приложению на любом домене выполнять аутентифицированные междоменные запросы к игре, потенциально похищая данные сессии.
<?xml version="1.0"?> <cross-domain-policy> <allow-access-from domain="*" /> </cross-domain-policy>
Отсутствие ограничения частоты запросов на аутентификацию
CRITICAL CVSS 8.1
Отсутствует ограничение частоты запросов, CAPTCHA или механизм блокировки аккаунта на эндпоинтах входа. Брутфорс-атаки могут перебирать неограниченное количество комбинаций паролей. AJAX-вход отправляет учётные данные через POST без какой-либо защиты от автоматизации.

Сессионные куки без флагов безопасности
CRITICAL CVSS 7.4
Игровые сервера (g1, g2, g3, turbo) устанавливают PHPSESSID без флагов Secure, HttpOnly или SameSite. Только avatar.botva.ru имеет частичные флаги (Secure + HttpOnly на странице редиректа, но игровые сервера их не имеют). Сессии могут быть украдены через XSS или MITM.
// avatar.botva.ru (redirect only) Set-Cookie: PHPSESSID=xxx; path=/; secure; HttpOnly; SameSite=none // g1.botva.ru, g2, g3, turbo (GAME SERVERS) Set-Cookie: PHPSESSID=xxx; path=/ // NO secure, NO HttpOnly, NO SameSite!
XSS-уязвимости — .html() без санитизации
CRITICAL CVSS 7.2
Более 30 случаев использования jQuery .html(data), где ответ сервера напрямую внедряется в DOM без санитизации. Если ответ сервера содержит вредоносный HTML/JS, это приводит к XSS. В сочетании с отсутствием CSP легко эксплуатируется.
// Direct server response injection (XSS vector) $('#body').html(data); // line 755 $('#l_popup').html(item.data); // line 755 $('#accordion').html(item.data); // line 755 // Fort report loading $('.tab[rel='+tab+']').append($(data).contents()); // line 102
jQuery 1.11.3 с известными CVE
CRITICAL CVSS 6.9
Основной JS-бандл использует jQuery 1.11.3 (апрель 2015) — 11 лет. Известные уязвимости: CVE-2019-11358 (prototype pollution), CVE-2020-11022/11023 (XSS через .html()). Админ-панель использует ещё более старый jQuery 1.10.2.
document.domain ослабляет изоляцию источников
CRITICAL CVSS 6.5
Главная страница устанавливает document.domain = 'botva.ru', что ослабляет политику одного источника (Same-Origin Policy) для всех поддоменов. Если любой поддомен скомпрометирован (XSS), он может получить доступ к DOM ВСЕХ других поддоменов, включая игровые сервера с активными сессиями.
// Line 34 of main HTML document.domain = 'botva.ru'; // Weakens Same-Origin Policy
Метаданные SVN-репозитория на продакшене
CRITICAL CVSS 6.5
Директория /.svn/ существует на продакшен-серверах (возвращает 403 вместо 404). Это указывает на то, что код развёртывается напрямую из SVN-checkout без процесса сборки. Частичный доступ может раскрыть структуру исходного кода и URL репозитория.
Игровой токен KEY передаётся в GET-параметрах
HIGH CVSS 6.1
Анти-CSRF токен (переменная KEY) передаётся в URL-строке запроса (?k=KEY) для игровых действий. GET-параметры записываются в логи доступа сервера, историю браузера и заголовки Referer — риск утечки токена.
// KEY sent in GET URL — visible in logs & Referer headers $.get('fort.php?fast_finish='+id+'&k='+KEY', function(result) {...}); $.get('?a=place&type=11&do_cmd=delete&log='+id+'&k='+KEY', ...);
Токены аутентификации в WebSocket
HIGH CVSS 6.0
Игровой клиент отправляет user_uid и user_auth в открытом виде через WebSocket при открытии соединения. Если WebSocket не использует WSS (TLS), эти учётные данные могут быть перехвачены.
onOpen: function() { this.send("auth " + user_uid + ' ' + user_auth"); }
6 вызовов eval() в основном бандле
HIGH CVSS 5.4
Основной JavaScript-бандл содержит 6 вызовов eval(). eval() выполняет произвольные строки как код — если какой-либо ввод контролируется пользователем, это приводит к инъекции кода. Современный JavaScript не имеет легитимных причин для использования eval().
Сайт поддержки: PHP 7.4.30 (EOL)
HIGH CVSS 5.3
support.destiny.games раскрывает X-Powered-By: PHP/7.4.30. PHP 7.4 достиг конца поддержки в ноябре 2022 — никаких патчей безопасности уже 3.5+ лет. Также работает WordPress (wp-json доступен).
Несогласованность версий Nginx на серверах
HIGH
Разные версии nginx указывают на несогласованное обновление. avatar/g3/turbo работают на 1.18.0 (2020, устарел), а g1/g2/i на 1.29.2 (актуальный). Старые версии могут иметь неисправленные уязвимости.
Использование innerHTML (5 случаев)
HIGH
Прямое присвоение innerHTML найдено в системе тултипов и других компонентах. В сочетании с отсутствием CSP создаёт дополнительную поверхность XSS-атаки помимо jQuery .html().
Поля паролей без autocomplete="off"
HIGH
Формы входа не имеют autocomplete="off" или autocomplete="new-password" на полях пароля. Браузеры могут кэшировать учётные данные в общих средах (интернет-кафе, общие компьютеры).
Yandex Вебвизор записывает ввод форм
HIGH
Яндекс Метрика с включённым Вебвизором может записывать нажатия клавиш пользователей в формах, потенциально перехватывая пароли. Конфигурация маскировки ввода не обнаружена в настройках трекинга.
Отсутствует robots.txt
MEDIUM
Файл robots.txt не найден (404). Поисковые системы могут индексировать критические пути как /admin/, страницы входа и внутренние эндпоинты.
DOCTYPE HTML 4.01 Transitional
MEDIUM
Использует устаревший DOCTYPE HTML 4.01 Transitional от 1999 года. Отсутствуют семантические элементы HTML5, роли ARIA и современные функции доступности.
Кодировка windows-1251
MEDIUM
Устаревшая кириллическая кодировка вместо UTF-8. Может вызывать искажение символов и исторически связана с методами обхода XSS на основе кодировки.
test.php на продакшене
MEDIUM
/test.php возвращает 200 OK с 0 байт и устанавливает PHP-сессию. Отладочные/тестовые файлы не должны существовать на продакшене — они могут принимать параметры, раскрывающие внутреннее состояние.
Отсутствует Content Security Policy
MEDIUM
Без CSP любая XSS-уязвимость может загружать внешние скрипты, передавать данные на любой домен и выполнять встроенный JavaScript без ограничений.
Раскрытие версии сервера
MEDIUM
Заголовок сервера раскрывает точные версии nginx и PHP, что упрощает злоумышленникам поиск известных уязвимостей для конкретных версий.
SameSite=none на куках
MEDIUM
Поддомен avatar устанавливает SameSite=none, что позволяет отправлять куки в межсайтовых запросах, делая возможными CSRF-атаки с любого домена.
347 объявлений !important в CSS
LOW
Чрезмерное переопределение специфичности указывает на плохую архитектуру CSS. 256 в основном CSS + 91 во второстепенном CSS-файле. Крайне затрудняет обслуживание.
Отсутствует Sitemap.xml
LOW
Отсутствие XML-карты сайта ухудшает SEO. В сочетании с отсутствием robots.txt поисковая оптимизация фактически отсутствует.
Вьюпорт фиксирован на 990px
LOW
<meta name="viewport" content="width=990"> — не адаптивный. Только 6 @media-запросов на 649 КБ CSS. Игра непригодна на мобильных устройствах.
Зависимости от Flash (ZeroClipboard)
LOW
Код ссылается на ZeroClipboard SWF для копирования в буфер обмена. Flash Player был прекращён в 2020 году — эта функция не работает во всех современных браузерах.
Устаревшие условные комментарии IE
LOW
HTML5 shiv загружен для совместимости с IE. IE был прекращён в 2022 — мёртвый код, увеличивающий вес страницы.
Отсутствуют роли ARIA и доступность
LOW
Ноль ARIA-атрибутов, нет семантических элементов HTML5, нет ссылок пропуска навигации, нет управления фокусом. Полностью недоступно для пользователей с ограниченными возможностями.

Рекомендации

НЕМЕДЛЕННО (на этой неделе)

1. Продлить SSL-сертификат — истекает через 12 дней
2. Заблокировать /admin/ через белый список IP или HTTP-аутентификацию
3. Добавить Secure, HttpOnly, SameSite=Strict ко всем сессионным кукам
4. Удалить crossdomain.xml или ограничить конкретными доменами
5. Скрыть версию nginx — server_tokens off;
6. Удалить test.php с продакшена
7. Заблокировать /.svn/ доступ на всех серверах единообразно

КРАТКОСРОЧНО (1-3 месяца)

1. Добавить CSRF-токены ко всем формам
2. Внедрить ограничение частоты запросов на эндпоинтах аутентификации
3. Добавить заголовки безопасности (CSP, X-Frame-Options и т.д.)
4. Обновить jQuery до 3.x (протестировать совместимость)
5. Заменить eval() безопасными альтернативами
6. Санитизировать все вызовы .html() через DOMPurify
7. Обновить nginx до 1.29.x на всех серверах
8. Деплоить через CI/CD, а не SVN checkout
9. Удалить назначение document.domain

ДОЛГОСРОЧНО (3-12 месяцев)

1. Мигрировать на кодировку UTF-8
2. Мигрировать на HTML5 с семантическими элементами
3. Добавить адаптивный дизайн / мобильную поддержку
4. Внедрить CSP с nonce-базированными встроенными скриптами
5. Добавить баннер согласия на куки и политику конфиденциальности
6. Оптимизировать ресурсы (минификация, сжатие, разделение кода)
7. Добавить роли ARIA и функции доступности
8. Настроить Web Application Firewall (WAF)
9. Внедрить полноценный мониторинг и оповещения
